# 한글담 v0.4

[![CI](https://github.com/HanyeolKo/hangeuldam/actions/workflows/ci.yml/badge.svg)](https://github.com/HanyeolKo/hangeuldam/actions/workflows/ci.yml)

HWP 5와 HWPX를 브라우저에서 읽고 편집한 뒤 **HWP 파일로 저장**하는 웹앱입니다. 편집기와 글꼴을 미리 저장하면 인터넷 없이도 사용할 수 있습니다.

문서 엔진은 Rust/WASM, 편집 화면은 기존 RHWP Studio의 JavaScript/TypeScript를 사용합니다. 파일 이름과 내용은 서버로 전송하지 않습니다. 이 저장소에는 앱 소스·라이선스·테스트·로컬 실행 도구가 들어 있으며 운영 서버 설정은 포함하지 않습니다.

## 문서 열기·편집·저장

1. `파일 열기`로 HWP 또는 HWPX를 선택하거나 화면에 끌어다 놓습니다. 예제 문서로 먼저 확인할 수도 있습니다.
2. 읽기 화면에서 쪽 이동, 확대·축소, 너비 맞춤, 텍스트 보기를 사용할 수 있습니다.
3. `편집하기`를 누르고 문서 내용을 클릭해 입력합니다. 편집기 도구에서 글자·문단 서식과 표를 편집할 수 있으며 실행 취소·다시 실행을 지원합니다.
4. `HWP 저장` 또는 `Ctrl+S`로 현재 문서를 `.hwp` 파일로 내려받습니다. HWPX에서 시작한 문서도 HWP로 저장합니다. 내보낸 파일은 같은 엔진으로 다시 열 수 있는지 검사하며, 엔진이 보존하지 못할 요소를 보고하면 저장 전에 확인을 요청합니다.
5. `읽기 보기`로 편집한 내용의 미리보기를 확인할 수 있습니다. 미리보기 전환만으로 파일이나 문서함에 저장되지는 않습니다.
6. `기기에 저장`을 누르면 현재 문서를 이 브라우저의 문서함에 보관합니다. 편집기를 연 뒤에는 현재 내용을 HWP로 내보내 저장하고, 편집기를 열지 않은 상태에서는 선택한 파일의 사본을 저장합니다.

원본 파일은 자동으로 덮어쓰지 않습니다. `원본 파일 다운로드`는 처음 연 파일의 바이트를 그대로 내려받으며, 편집 내용은 `HWP 저장`으로 별도 보관합니다. 브라우저의 다운로드 안내에서 저장 위치를 확인하세요. 문서 닫기나 다른 파일 열기 시 저장하지 않은 변경사항이 있으면 확인을 요청합니다.

## 전체화면과 기기별 화면

문서 위 `전체화면` 버튼은 읽기·편집 화면을 넓히며 제목·저장 도구를 유지합니다. 버튼이나 Esc로 종료합니다. 브라우저가 전체화면 API를 지원하지 않으면 `화면 확대`로 앱 안의 문서 영역을 넓힙니다. 이 경우 브라우저 주소창은 유지됩니다.

모바일·태블릿·PC 분류는 브라우저 기기 정보와 터치 신호로 정하며, 창 너비만으로 기기 종류를 바꾸지 않습니다. iPad의 데스크톱 브라우저 표시도 고려합니다. 화면 상단의 `화면 보기`에서 언제든 자동·모바일·태블릿·PC를 선택할 수 있습니다. 전체화면에서는 문서 도구의 같은 선택기를 사용합니다. 화면 모드를 바꾸어도 열린 문서와 편집 내용은 유지됩니다. 모바일은 접이식 문서함과 큰 터치 도구를 제공하고, 태블릿은 서식 도구를 유지합니다. 편집기의 `글 입력`, `폭 맞춤`, 확대·축소 도구를 사용할 수 있습니다.

기기별 검증은 Chromium의 모바일·태블릿 UA 및 터치 에뮬레이션으로 진행했습니다. 실제 iOS Safari의 가상 키보드와 정밀 터치 선택은 추가 실기기 검증이 필요합니다.

## 키보드 단축키와 KEYMAP

상단 또는 문서 도구의 키보드 버튼에서 **41개 명령**의 단축키와 실행 버튼을 확인할 수 있습니다. PC·모바일·태블릿의 명령과 키 조합은 같습니다. 모바일·태블릿은 외장 키보드를 쓰거나 도움말의 `실행`을 누를 수 있습니다. 복사·잘라내기·붙여넣기는 키보드 또는 브라우저·편집기 메뉴를 사용합니다. Mac은 Ctrl 대신 ⌘ Command, Alt 대신 ⌥ Option을 사용합니다.

| 동작 | 단축키 |
| --- | --- |
| 파일 열기 / HWP 다운로드 | Ctrl/⌘ + O / S |
| 이 브라우저에 기기 저장 | Ctrl/⌘ + Shift + S |
| 원본 파일 다운로드 | Alt/⌥ + Shift + O |
| 문서 닫기 | Ctrl/⌘ + Shift + X |
| 편집·읽기 전환 | Ctrl/⌘ + Shift + E |
| 전체화면 전환 | Ctrl/⌘ + Shift + F |
| 문서 확대·축소 / 100% | Ctrl/⌘ + + 또는 − / 0 |
| 문서 너비 맞춤 | Alt/⌥ + Shift + F |
| 텍스트 보기 (읽기) | Alt/⌥ + Shift + T |
| 이전·다음 쪽 (읽기) | Page Up / Page Down |
| 첫·마지막 쪽 (읽기) | Ctrl/⌘ + Home / End |
| 실행 취소 / 다시 실행 | Ctrl/⌘ + Z / Shift + Z (또는 Ctrl/⌘ + Y) |
| 전체 선택 / 복사·잘라내기·붙여넣기 | Ctrl/⌘ + A / C·X·V |
| 문서에서 찾기 / 찾아 바꾸기 | Ctrl/⌘ + F / F2 |
| 다음 검색 결과 | F3 |
| 굵게·기울임·밑줄 | Ctrl/⌘ + B·I·U |
| 글자 크기 키우기·줄이기 | Ctrl/⌘ + ] / [ |
| 글자 모양 / 문단 모양 | Alt/⌥ + L / T |
| 쪽 나누기 | Ctrl/⌘ + Enter |
| 단축키 도움말 | F1 또는 Ctrl/⌘ + / |
| 대화상자 닫기·전체화면 종료 | Esc |

정렬, 취소선, 줄 간격 등 나머지 명령은 앱 도움말에서 확인하세요. 편집 명령은 편집 영역에 커서를 둔 상태에서 사용합니다. 한글 조합 중에는 단축키를 실행하지 않으며, 도움말·편집 대화상자가 열린 동안에는 해당 대화상자의 입력을 우선합니다. 클립보드 단축키는 브라우저가 제공하는 신뢰된 입력 경로를 유지합니다. 운영체제가 먼저 사용하는 키는 화면의 실행 버튼으로 같은 명령을 사용할 수 있습니다.

[public/KEYMAP.js](public/KEYMAP.js)가 명령 ID, 이름, 사용 범위, 키 조합, `handler`와 엔진 `command`를 정의합니다. [public/shortcuts.js](public/shortcuts.js)의 명령 레지스트리가 이를 실제 앱 함수 및 편집기 명령에 연결하고 도움말을 생성합니다. 새로운 동작은 레지스트리에 함수를 등록한 뒤 KEYMAP에 연결합니다. 단순 키 변경은 KEYMAP에서 수정합니다. 복사·붙여넣기 키는 브라우저의 신뢰된 클립보드 이벤트를 유지하도록 기존 편집기에 위임합니다. 수정 후에는 `npm run build`로 오프라인 자산 목록을 갱신하세요.

## 오프라인 사용과 개인정보

온라인 상태에서 `오프라인 사용 준비`를 누릅니다. 다운로드는 앱 파일의 전체 바이트 대비 준비한 용량의 **%**로 표시합니다. 완료되면 같은 버튼이 **`오프라인 준비 테스트`**로 바뀝니다. 테스트는 사용자가 이 버튼을 누를 때만 실행하며, 다운로드 직후 자동으로 실행하지 않습니다. 테스트는 저장된 앱·글꼴·문서 엔진과 자체 예제로 문서 열기, 편집, HWP 생성 및 재열기를 확인합니다. 사용자 문서나 문서함 사본은 변경하지 않습니다.

이후 **같은 브라우저·프로필·주소**를 열면 인터넷 없이 문서를 열고 편집하거나 HWP로 저장할 수 있습니다. 브라우저 메뉴에서 앱을 설치해 다시 실행할 수도 있습니다. 일반 `페이지 저장` / `페이지 다운로드` 파일로 편집기를 실행하는 방식은 지원하지 않습니다. 편집기는 HTML 외에 WASM·Worker·글꼴 등 앱 자산 전체가 필요하며, 앱의 오프라인 준비가 이를 저장합니다. 자세한 배경은 [Chrome의 페이지 다운로드 안내](https://support.google.com/chrome/answer/7343019?co=GENIE.Platform%3DAndroid&hl=ko)와 [PWA 캐시 안내](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching)를 참고하세요.

이전 버전을 준비해 두었다면 온라인 상태에서 앱을 다시 열고 최신 버전의 준비를 완료하세요. 앱의 테스트는 기기 전체 인터넷 설정을 변경하지 않습니다. 실제 연결을 끊은 상태도 확인하려면 준비 완료 후 비행기 모드 또는 Chrome 개발자 도구의 Offline 설정에서 같은 주소를 새로고침하세요. 브라우저 저장 데이터를 지우면 다시 준비해야 합니다.

파일 선택, 문서 해석, 편집, HWP 생성은 브라우저에서 처리합니다. **문서 내용과 파일명은 서버로 전송하지 않습니다.** 서버는 앱·엔진·글꼴·예제 등 정적 자산을 제공합니다. AI·클라우드 변환·원격 웹 글꼴을 사용하지 않으며 문서의 외부 링크 이동과 폼 실행을 차단합니다.

`내 문서함`은 사용자가 `기기에 저장`을 눌렀을 때 IndexedDB에 저장합니다. 이와 별도로 내장 Studio는 편집 중 **복구 초안을 브라우저 로컬 저장소에 자동 저장할 수 있습니다.** 최근 편집 문서의 이름·형식·시간도 이 브라우저에 기록됩니다. 복구 초안은 다운로드한 HWP나 명시적으로 저장한 문서함 사본을 대신하지 않습니다. 문서함의 삭제 버튼은 문서함 사본을 지우며, 복구 초안·최근 기록까지 지우려면 브라우저에서 이 사이트의 저장 데이터를 삭제하세요.

문서함, 복구 초안, 오프라인 앱 캐시는 브라우저·프로필·접속 주소별로 분리됩니다. 브라우저 데이터 삭제, 시크릿 창 종료, 저장 공간 정리로 유실될 수 있습니다. 중요한 문서는 `HWP 저장`으로 별도 파일을 보관하세요. 문서함에서 사본을 삭제해도 사용자가 처음 선택한 원본 파일은 유지됩니다.

## 로컬 실행과 오프라인 사용

이 저장소를 복제하거나 GitHub의 Code → Download ZIP으로 내려받아 압축을 풉니다. Python 3이 이미 설치되어 있어야 하며 npm이나 인터넷 연결은 실행에 필요하지 않습니다.

- Linux/macOS: `sh start-offline.sh`
- Windows: `start-offline.bat`
- 브라우저에서 `http://localhost:8787/`에 접속합니다.

직접 HTML 파일을 더블클릭하는 `file://` 방식은 WASM·Worker 제약 때문에 지원하지 않습니다. 위 서버는 해당 PC의 localhost에만 바인딩합니다. 포트를 바꾸려면 `python3 scripts/serve.py --port 8788`을 실행합니다.

원본 RHWP 소스와 Studio 수정 패치도 배포 폴더의 [public/source/](public/source/)에 제공합니다. 큰 소스 아카이브는 오프라인 앱 캐시에 자동 저장하지 않으므로, 웹에서 설치한 앱만 가지고 인터넷을 끊으면 소스 ZIP 다운로드는 사용할 수 없습니다. 실행에 필요한 파일과 고지 원문은 별도로 캐시합니다.

## 구현

| 구성 | 사용 기술 |
| --- | --- |
| 문서 해석·조판·HWP 생성 | Rust `@rhwp/core@0.9.0`의 사전 컴파일 WASM |
| 문서 편집 | RHWP Studio v0.9.0 자체 호스팅 및 `@rhwp/editor@0.9.0` SDK |
| 화면·파일 입력·문서함 | HTML, CSS, JavaScript 모듈, IndexedDB |
| 읽기 화면의 문서 처리 | Web Worker, OffscreenCanvas, Worker 글꼴 로딩 |
| 오프라인 앱 | Service Worker, 버전별 Cache Storage, PWA manifest |
| 읽기 화면의 SVG 표시 | DOMPurify 3.4.17 및 외부 자원·활성 콘텐츠 차단 |
| 글꼴 | 자체 호스팅 Nanum 및 Studio에 동봉한 공개 글꼴 |

Rust 엔진과 편집기는 기존 오픈소스를 재사용했습니다. 이 프로젝트는 UI, 로컬 저장, 오프라인 실행, HWP 내보내기 확인 및 배포를 통합합니다. 현재 배포·실행에는 Rust 컴파일러가 필요하지 않습니다. Studio의 변경사항과 재빌드 방법은 [vendor-sources/BUILD.md](vendor-sources/BUILD.md)에 있습니다.

## 지원 범위와 제한

- HWP 5 / HWPX 입력, 최대 50 MiB. 읽기 화면은 최대 5,000쪽을 한 번에 한 쪽씩 렌더링하며 Worker 작업에 60초 제한을 둡니다.
- HWP 파일로 저장합니다. HWPX 재저장 버튼은 제공하지 않습니다. 저장 결과는 별도 엔진 인스턴스로 재해석해 검사했으며, 한컴 한글 데스크톱 프로그램에서 직접 여는 검증은 수행하지 않았습니다.
- 문단, 글자 서식, 표, 그림, 쪽 나눔을 포함한 샘플을 대상으로 테스트합니다. 복잡한 도형·수식·전용 글꼴 등 모든 한글 기능의 완전한 재현이나 무손실 저장을 보장하지 않습니다. 저장 전 경고와 저장한 문서의 결과를 확인하세요.
- HWP 3, OCR, 암호 문서의 암호 입력은 지원하지 않습니다. 편집기 저장 어댑터는 암호 문서를 평문으로 내보내는 작업을 거절합니다.
- 읽기 화면에서 외부 링크·원격 그림·스크립트·SVG 애니메이션을 차단하고, 편집기에서도 외부 탐색·폼 동작을 차단합니다. 삽입된 일반 래스터 그림은 표시합니다.
- 브라우저의 오프라인 캐시에는 정상 HTTPS 또는 localhost가 필요합니다.
- 검증 대상은 Chromium 데스크톱 및 모바일·태블릿 에뮬레이션입니다. 실제 iOS Safari·가상 키보드의 호환성은 별도 실기기 검증이 필요합니다.

## 개발 및 검증

호스트 앱 개발에는 Node.js 18 이상과 Python 3을 사용합니다. 내장 Studio를 재빌드할 때는 별도 [빌드 기록](vendor-sources/BUILD.md)의 Node 버전과 명령을 따르세요. 온라인 개발 환경에서:

```sh
npm ci
npx playwright install chromium
npm run test:fixtures
npm test
```

테스트는 로컬 서버를 자동 실행합니다. 외부 `pyhwp`와 `hwpxlib`의 고정 커밋 문서를 SHA-256 검증 후 `.test-data/fixtures/`에 받습니다. 출처와 저장소 라이선스는 [tests/fixtures.json](tests/fixtures.json)에 있습니다. 이 QA 문서들은 공개 앱과 저장소에 포함하지 않습니다.

읽기·원본 다운로드 테스트와 함께 편집 입력, 실행 취소·다시 실행, HWP 내보내기 후 재열기, 표·서식 유지, 저장소, 오프라인 동작을 검사합니다. 테스트 통과는 전체 HWP 형식의 호환성이나 보안 감사를 의미하지 않습니다.

`public/` 실행 파일을 수정한 뒤에는 반드시 `npm run build`로 `sw.js`의 캐시 버전을 갱신해야 합니다. 캐시 목록에는 편집기·엔진·글꼴·라이선스가 포함되며 모든 실행 자산을 저장한 뒤에만 오프라인 준비 완료로 표시합니다. `public/source/`의 원본 소스 다운로드는 캐시 대상에서 제외합니다. 호스트 앱의 일반 소스 수정에는 번들러가 필요하지 않습니다.

의존성 버전을 바꾸면 배포 파일, 라이선스, Studio 빌드 기록도 함께 갱신해야 합니다. 라이브러리는 CDN에서 실행하지 않습니다. Studio npm 런타임 의존성과 개발 도구는 감사 범위가 다르므로 개발 도구를 포함해 취약점이 없다고 일괄 표기하지 않습니다.

## CI와 배포 산출물

GitHub Actions는 main push와 Pull Request를 GitHub 호스팅 환경에서 검사합니다. 고정된 의존성과 테스트 문서를 설치하고, 오프라인 캐시를 만든 뒤 브라우저 테스트를 실행합니다. main push의 검사가 모두 통과하면 파일별 SHA-256과 커밋 정보를 담은 `hangeuldam-static` artifact를 발행합니다.

운영 배포기는 성공한 main 빌드의 정적 파일만 검증해 받도록 별도로 구성합니다. 서버 주소·인증 정보·운영 설정은 이 공개 저장소에 포함하지 않습니다. 외부 PR 코드는 운영 PC에서 실행하지 않습니다.
